RIT API

Monks Case v1.0

Autenticação

1. Geral & Sessão

POST /session/ GET /login-users/

2. Dashboard

GET /team/dashboard/ GET /team/history/

3. Avaliações (RIT)

POST /evaluations/ GET /evaluations/recent/

4. Configurações

GET /questions/versions/current/ POST /questions/versions/

Documentação de Endpoints

A API segue o padrão REST e retorna respostas no formato JSON. Você pode testar as requisições diretamente por aqui.

Atenção: Certifique-se de que o container do Docker (backend) está rodando localmente na porta 8000 para que as funções de Testar funcionem sem erros de rede.

Autenticação

A API utiliza Custom Headers para identificar o usuário logado. Para endpoints marcados como Autenticado, injetaremos o header `X-User-Email` utilizando o valor preenchido abaixo:

1. Geral & Sessão

POST /api/session/
Público

Inicia a sessão e valida a existência do e-mail do usuário no sistema.

Request Body (JSON)

{
  "email": "macielniiicolas@gmail.com"
}

200 OK

                      
{
  "id": 16,
  "name": "Nicolas Maciel",
  "email": "macielniiicolas@gmail.com",
  "position_name": "Software Analyst"
}

                    

                    

                      
404 Not Found

                      
{
  "error": "User not found"
}

3. Avaliações (RIT)

          
          
          

            

              

                POST
                /api/evaluations/
              

              

                Autenticado
                
              

            

            

              
Submete as notas de uma avaliação de desempenho para um membro da equipe.

              
              

                

                  
Request Body (JSON)

                  

                    
                    
                  

                


{
  "lead_id": 10,
  "ratings": [
    { "question_id": 1, "score": 5 },
    { "question_id": 2, "score": 4 }
  ]
}


                


                

                  
Exemplos de Resposta

                  

                    

                      
201 Created

                      
{
  "message": "Avaliação enviada com sucesso."
}

                    

                    

                      
400 Bad Request

                      
{
  "error": "Cooldown ativo. Você só pode avaliar este funcionário novamente em 4 dias."
}

                    

                    

                      
403 Forbidden

                      
{
  "error": "Você não tem permissão para avaliar este funcionário."
}

                    

                  

                

              

            

          


          
          

            

              

                GET
                /api/evaluations/recent/?lead_id=10
              

              

                Autenticado
                
              

            

            

              
Verifica se o funcionário (lead_id) já foi avaliado dentro da janela de cooldown (7 dias). Utilizado para bloquear múltiplas avaliações em curto período.

              
              

                
              

              

              
              

                
Exemplos de Resposta

                

                  

                    
200 OK

                    
{
  "has_recent": true,
  "days_remaining": 4
}

                  

                

              

            

          

        


        
        

          
4. Configurações Globais (Admin)

          
          
          

            

              

                GET
                /api/questions/versions/current/
              

              

                Autenticado
                
              

            

            

              
Retorna o bloco de perguntas da "versão ativa" do sistema de avaliações, englobando os pesos individuais para o cálculo RIT.


              

                
              

              


              

                
Exemplos de Resposta

                

                  

                    
200 OK

                    
[
  {
    "id": 1,
    "title": "Entrega de Resultados",
    "weight": 25
  },
  {
    "id": 2,
    "title": "Qualidade Técnica",
    "weight": 25
  }
]

                  

                

              

            

          


          
          

            

              

                POST
                /api/questions/versions/
              

              

                Restrito: CEO, CTO, CFO
                
              

            

            

              
Gera uma nova versão de formulário. Todos os relatórios gerados a partir deste ponto utilizarão essa nova composição para seus cálculos de performance.

              
              

                

                  
Request Body (JSON)

                  

                    
                    
                  

                


{
  "questions": [
    { "title": "Entrega de Resultados", "weight": 25 },
    { "title": "Execução e Qualidade", "weight": 20 }
  ]
}


                

                
                

                  
Exemplos de Resposta

                  

                    

                      
201 Created

                      
{
  "message": "Nova versão de formulário criada com sucesso."
}

                    

                    

                      
403 Forbidden

                      
{
  "error": "Apenas membros da diretoria (C-Level) podem alterar métricas globais."
}
